## 2. Core Code Breakdown

### A. Samurai Animation and Control (`runner_game/player.gd`)
We avoided large autogenerated `.tscn` sheets by loading the Samurai spritesheets dynamically and managing horizontal frames (`hframes`) inside a lightweight update function. 

* **State Animation Engine**:
  ```gdscript
  func set_anim(anim: String) -> void:
	  if current_anim == anim:
		  return
	  current_anim = anim
	  anim_frame = 0.0
	  match anim:
		  "run":
			  sprite.texture = RUN_TEX
			  sprite.hframes = 16
		  "jump", "fall":
			  sprite.texture = IDLE_TEX
			  sprite.hframes = 10
  ```
* **Movement and Physics**: The character sits at a fixed X offset (`200`) and uses `move_and_slide()` with vertical gravity. Pressing Space or Up Arrow applies a vertical velocity upward (`JUMP_VELOCITY`).

### B. Infinite Floor Scrolling (`runner_game/runner_game.gd`)
To simulate running at speeds up to 1000+ pixels per second without running out of bounds, we scroll two static ground bodies (`Floor1` and `Floor2`) leftwards:
```gdscript
floor1.position.x -= speed * delta
floor2.position.x -= speed * delta

if floor1.position.x <= -FLOOR_WIDTH:
	floor1.position.x = floor2.position.x + FLOOR_WIDTH
```
This guarantees an infinite floor loop with zero physics boundary hiccups.

### C. Dynamic Difficulty Spawning
To make the runner challenging, the speed increases proportionally to the survival score. The spawning timer wait time is shortened progressively to increase obstacles frequency:
```gdscript
speed = base_speed + (score * 1.5)
var min_time = clamp(1.2 - (speed * 0.0005), 0.8, 1.5)
var max_time = clamp(2.5 - (speed * 0.0008), 1.4, 2.5)
spawn_timer.wait_time = randf_range(min_time, max_time)
```

### D. Game State Management
Pause and Game Over UI screens are instantiated over the active scene dynamically. By declaring:
```gdscript
process_mode = Node.PROCESS_MODE_ALWAYS
```
the UI layers receive mouse clicks and input callbacks even when the main physics engine is completely suspended (`get_tree().paused = true`).
